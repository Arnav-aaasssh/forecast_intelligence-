# Enterprise Forecast Decision Intelligence Platform - UI Components

This document outlines the core UI components of the dashboard, describing what they represent and how they map to the backend data from `report.json`.

## 1. Global Navigation & Filtering

### Global Filters Bar
- **Representation**: A top horizontal bar with dropdowns for `Region`, `Sub-Region`, `Fiscal Week`, and `Channel`.
- **Backend Data**: Populated dynamically by extracting unique values from the `RAW_LEVEL1` array in `report.json`.
- **Interaction**: Changing a filter updates the global state (`CURRENT_FILTERS`) and triggers a re-render of all downstream components using the `computeHierarchyRollup` JavaScript function.

### Sidebar Navigation
- **Representation**: Left-hand rail allowing the user to switch between views (Executive Summary, Strategy Assessment, Model Champion, Business Context, Anomaly Detection).
- **Interaction**: Toggles the visibility of standard `<section>` blocks within the HTML.

## 2. Executive Summary View (`#page-exec`)

### Decision Cockpit (Operational Decision)
- **Representation**: A massive, high-contrast banner at the top of the page. It displays a binary recommendation: either "Deploy ML for [Filter Level]" (Teal) or "Manual Override Required" (Navy/Red).
- **Backend Data**: Rendered by calculating the total `Queue_Wins_ML` vs `Queue_Wins_Manual` for the currently filtered subset of `RAW_LEVEL1` data. The winner dictates the text and color.

### Executive KPI Cards
- **Representation**: A grid of four cards displaying high-level metrics: Forecast Accuracy, Actual Volume, Overall Mean WAPE, and Aggregate Forecast Bias.
- **Backend Data**: If no filters are applied, this pulls directly from `report.json.level0`. If filters are applied, the JS recalculates these sums and averages on the fly from the filtered `level1` data.

### Reveal Cards (Analytical Insights)
- **Representation**: Wide textual cards that provide narrative context (e.g., explaining a systemic shift). They expand vertically based on content and flip/expand on hover to show deeper technical details.
- **Backend Data**: Hardcoded or populated from specific summary narrative fields in the JSON payload (like structural contraction percentages).

## 3. Strategy Assessment View (`#page-sa`)

### Hierarchy & Queue Decision Table
- **Representation**: A detailed data table comparing ML vs. Manual performance. It lists the subgroups (e.g., Sub-Regions if Region is selected), their Volume, ML WAPE, Manual WAPE, and the Recommended Decision.
- **Backend Data**: Generated by passing the filtered `RAW_LEVEL1` data through `computeHierarchyRollup()`. The "Recommended Decision" column evaluates which method won the most queues within that specific row's subgroup.

### Performance Drift Chart
- **Representation**: A `Chart.js` bar chart comparing the ML error vs. the Manual error across different segments.
- **Backend Data**: Plotted using the aggregated WAPE arrays generated from the `computeHierarchyRollup()` output.

## 4. Model Champion View (`#page-mc`)

### Algorithmic Leaderboard
- **Representation**: A ranked table of different ML architectures (e.g., Prophet, XGBoost, LightGBM) showing their composite scores and runtime metrics.
- **Backend Data**: Rendered from `report.json.champions`, an array of objects detailing the performance of individual models against the validation dataset.

## 5. Business Context View (`#page-bc`)

### Macroeconomic Contraction Chart
- **Representation**: A `Chart.js` line chart showing historical baseline volume abruptly dropping against actual realized volume.
- **Backend Data**: Rendered from a time-series array (e.g., `report.json.context.timeseries`), plotting the baseline trajectory vs actuals to visually prove the systemic shift that caused tree-based models to fail.

## 6. Anomaly Detection View (`#page-ad`)

### Structural Break Grid
- **Representation**: A grid of cards or a table highlighting specific queues that experienced massive, unexpected variance (anomalies).
- **Backend Data**: Rendered from `report.json.anomalies`, pulling specific queue IDs, their variance magnitude, and the classification of the anomaly type.
