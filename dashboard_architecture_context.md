# Enterprise Forecast Decision Intelligence Platform - Architecture & Context

## 1. Project Context
The Enterprise Forecast Decision Intelligence Platform is a specialized frontend dashboard built to provide executive oversight into the performance of Machine Learning (ML) forecasts versus Manual (human) forecasts. 

Its primary goal is to determine if the ML models have achieved a sufficient level of accuracy and robustness to take over forecasting completely unsupervised. The core evaluation methodology relies on a "democratic queue-counting" approach: rather than comparing massive aggregated volume errors (which can allow a single large queue to skew the results), the system evaluates the ML vs. Manual WAPE (Weighted Absolute Percentage Error) on a queue-by-queue basis. The overarching "Winner" for a Region or Global level is decided by whichever method won the most individual queues.

## 2. File Structure

The production code is contained entirely within the `/dashboard` directory to ensure portability.

```text
/dashboard
│
├── index.html                  # Main application structure and styling
├── js/
│   └── dashboard2_app.js       # Core business logic, data filtering, and rendering
├── css/
│   └── styles.css              # (Optional/Externalized) Styling overrides
└── data/
    └── report.json             # Static JSON payload acting as the backend database
```

## 3. Main Files & Functionalities

### `dashboard/index.html`
- **Purpose**: The master entry point. It is built as a Single Page Application (SPA).
- **Functionality**:
  - Contains the complete HTML scaffolding for the sidebar navigation and all the different views (Executive Summary, Strategy Assessment, etc.).
  - Contains the inline CSS design system (color tokens, typography, grid layouts, glassmorphism effects).
  - Acts as the mounting point for the JavaScript logic, defining the DOM IDs that the JS will inject data into.

### `dashboard/js/dashboard2_app.js`
- **Purpose**: The engine of the dashboard. Pure Vanilla JavaScript.
- **Functionality**:
  - **Data Ingestion**: Fetches `report.json` on `DOMContentLoaded`.
  - **State Management**: Maintains a `CURRENT_FILTERS` state object that tracks the user's selections for Region, Sub-Region, Fiscal Week, and Channel.
  - **Data Aggregation (`computeHierarchyRollup`)**: A critical function that takes the raw queue-level data (`RAW_LEVEL1`), applies the current filters, groups the data by the next logical hierarchy level, and tallies up the queue wins (`Queue_Wins_ML` vs `Queue_Wins_Manual`) to declare a winner.
  - **Component Rendering**: Contains functions like `renderExecutiveOverview()` and `renderHierarchyTable()` that dynamically update the DOM based on the filtered data.
  - **Charting**: Instantiates and updates `Chart.js` visualisations.

### `dashboard/data/report.json`
- **Purpose**: The data payload generated by backend Python scripts.
- **Functionality**:
  - **`level0`**: Pre-calculated global summary metrics (total volume, overall ML WAPE, etc.).
  - **`level1`**: Highly granular array of objects representing individual forecast queues. Each object contains `Region`, `SubRegion`, `Channel`, `FiscalWeek`, `Actual_Volume`, `ML_WAPE`, `Manual_WAPE`, and the queue-level winner. The JavaScript uses this array to perform all dynamic aggregations.
